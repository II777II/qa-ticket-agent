# 讲法与追问应对

## 30 秒电梯陈述

「这是一个电商平台的智能客服 Agent POC。核心链路是：自然语言提问 → read/write/human 三类意图路由；read 内按规则确定性调用知识库或订单工具，售后业务只有在用户确认后才创建工单，另有订单查询页与知识库检索页。
后端 FastAPI + LangGraph，模型和确定性业务分支分离；前端 React + Ant Design X；模型、记忆、检索和工单存储都走配置化装配。」

## 高频追问

**为什么不用 Dify / FastGPT 这类平台？**
POC 阶段它们确实能省一周工作量，但两个原因让我选自研最小编排：一是这个岗位要考的是「Agent 全栈 + 编排理解」，平台把 Graph、记忆、工具调用都藏起来了，讲不清内部；二是客户现场常有内网、私有化、审计要求，能自己控制编排与数据落点更稳。真要在现场抢时间，我会用平台搭第一版验证业务拆解，再用这套最小实现替换关键链路。

**RAG 召回不准怎么办？**
先定位是召回问题还是排序问题：加日志把命中片段与分数打出来。改进按性价比排序：① 分块策略（HTML 现在按 h2 切，表格/步骤类文档可以按语义切）；② 混合检索（关键词 + 向量，关键词兜住订单号、错误码这类专有词）；③ 查询改写（把「钱什么时候退回来」扩展成「退款到账时间」）；④ 加重排模型；⑤ 提示词约束「资料里没有就直说」。我实测撞到过：问「VPN 691 怎么办」时词频检索会把长句排到前面——同类问题在电商场景就是「退款多久到账」被其他退款条款挤掉，这就是要上向量与重排的直接理由。

**怎么防止模型幻觉乱建单？**
模型只生成售后草稿，不拥有建单工具；业务类型、订单号、联系人和描述先做槽位校验。只有用户在右侧核对并调用 `service-actions` 后才创建工单，存储层再按联系人和标题做重复拦截。

**多轮记忆怎么做的？上下文溢出怎么办？**
POC 用 `MemorySaver`，按 `thread_id` 隔离，只存进程内存。生产换 `PostgresSaver` 就有长期记忆与多实例共享。上下文控制有三招：检索到的参考资料不进消息历史（每轮临时拼），只留对话消息；超出阈值时把早期轮次摘要压缩；必要时按话题切新 thread。

**为什么用 SSE 不用 WebSocket？**
这个场景是单向流式输出，SSE 足够且更简单：HTTP 语义、能走现有网关与鉴权、断线自动重连。前端消费时不能用 `EventSource`（只支持 GET、不能带请求体），所以用 `fetch` + `ReadableStream` 手工解析事件流——这也是我把解析封在 `api/agent.ts` 的原因。要双向（比如多人协作、语音打断）再换 WebSocket。

**性能怎么考虑？**
链路上最慢的是模型，其次是工具里的写盘。现在工具是同步函数，FastAPI 的同步接口会走线程池，不会阻塞事件循环；工单写盘是「临时文件 + 原子替换」加线程锁，保证并发安全。再往上就是：把检索与建单做成异步任务、加 Redis 缓存热点查询、把检索从进程内换成向量库分批预热。

**可观测性做了什么？**
结构化日志（时间/级别/logger/消息），一轮对话的关键节点都有记录；SSE 事件可在前端按会话追踪；可选 Langfuse 记录 LangGraph、模型和检索调用，进程内指标记录 Token、延迟、错误率和意图分布。

**权限与数据隔离？**
POC 没做，这是明确的边界。生产要补：登录与 RBAC（消费者/售后专员/管理员）、按用户或商家过滤订单/知识库/工单可见范围、工具调用前的权限校验（比如只有本人能查自己的订单）、审计日志。技术上就是在 FastAPI 中间件里注入身份，把 `user_id` 传到工具与检索的过滤条件里。

**这套东西怎么部署？**
POC 本地单进程：前端构建产物由后端同源托管（一个地址），或开发时前后端分离两个端口。生产用 Docker Compose：后端容器 + Postgres（工单表 / 长期记忆 / pgvector）+ Redis，前端由 Nginx 或后端托管；再往上 K8s、健康检查、滚动升级。`docker/` 目录里已经放好落点和升级对应关系。

**这个 POC 明确没做什么？**
长期记忆 Store、权限与数据隔离、Redis 缓存、异步任务队列、监控告警、CI/CD、压测与真实业务数据导入属于生产化范围。POC 已提供 40 条固定评测集，在运营概览展示规则意图准确率、read 工具准确率和 RAG Top-3 命中率；这些是回归基线，不代表线上真实准确率。

## 讲的时候容易踩的坑

1. 不要把演示模式的占位回答说成「模型输出」——演示模式的价值是链路可见，不是效果。
2. 不要说「我们做了向量检索」：现在就是关键词命中与标题加权，如实说反而显得清楚边界。
3. 不要背数字：准确率、首 token 时间这些要现场测或标成「目标值」。
4. 主动说清哪块是「预留但没实现」（P-E-V-S 四节点、PostgresSaver、pgvector），比被追问出来更好。
