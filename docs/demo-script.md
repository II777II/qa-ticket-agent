# 演示脚本（3 分钟）

## 演示前 5 分钟准备

```powershell
conda activate qa-ticket
cd E:\Code\chatgpt\qa-ticket-agent

# 想要干净的工单看板就先删掉历史数据（可选）
Remove-Item backend\data\tickets.json -ErrorAction SilentlyContinue

# 前端产物已构建时，后端一个地址全包：http://127.0.0.1:5179/
npm --prefix frontend run build
python -m uvicorn backend.api.app:app --port 5179
```

检查清单：

- 浏览器只开一个标签：`http://127.0.0.1:5179/`（同源托管，不依赖 Vite）；开发调试时才用 `npm run dev` 的 5173。
- 顶部状态条应显示：模型（演示模式 / deepseek）、记忆 memory、工单 json、检索 memory。
- 录屏前先跑一轮问答预热（第一次请求要等依赖与检索索引就绪）。
- 有 Key 时把 `.env` 的 `LLM_PROVIDER` 切成 `deepseek`；没 Key 就用演示模式，**不要临场填 Key**。

## 兜底预案

| 现场情况 | 处理 |
| --- | --- |
| 没有 API Key | 演示模式全链路可跑，回答是占位内容，但建单、检索、引用、记忆都是真的，如实说明即可 |
| 现场网络不通 | 演示模式不联网；知识库检索在进程内，也不受影响 |
| 模型首 token 慢 | 主动报首 token 时间与总耗时，并说明这是同步工具 + 单进程 POC 的已知限制 |
| 端口被占 | 换端口启动：`--port 5180`；或用 `Get-NetTCPConnection -LocalPort 5179` 找占用进程 |
| 前端页面异常 | 同时跑 `npm run dev`（5173）对比，能区分是构建产物问题还是后端问题 |

## 不要做的事

- 不要在演示中改 `.env` 或重启服务：POC 没有热加载，重启会清空内存记忆。
- 不要只演 happy path。主动讲清没做的部分——长期记忆、权限、Redis、监控、CI/CD——比被问出来更可信。
